📝 ТЕХНІЧНИЙ ПАСПОРТ ПРОЄКТУ: WeekEnds BackendПризначення: REST API сервер для Android-додатка (управління розкладом робіт, локаціями, операціями та медіа-галереєю).Стек технологій: Java 21, Spring Boot 3.2.4, Spring Security 6.x (JWT, Stateless), Spring Data JPA, MySQL 8, SLF4J (Logging), Maven.

1. Архітектурна структура (Layered Architecture)Проєкт побудовано за класичною чотирирівневою архітектурою:domain (Entity): Моделі бази даних ORM (JPA/Hibernate) [см. Location выше].dao (Repository): Шар прямого доступу до MySQL (Spring Data JPA) [см. LocationRepository выше].service / service.impl: Бізнес-логіка, транзакційність (@Transactional), логування [см. LocationServiceImpl выше].controller: REST-ендпоінти, що приймають та повертають виключно JSON через DTO [см. DayController выше].

2. Схема бази даних & Зв'язки сутностей (MySQL)Всі зв'язки налаштовані через каскадне видалення CascadeType.ALL [см. Location выше]. Видалення батьківського елемента чисто очищує базу від залежних записів [см. Location выше, Day выше].User (Таблиця user): id (IDENTITY) ➡️ email (унікальний логін) ➡️ password (хеш BCrypt) ➡️ firstname ➡️ lastname ➡️ role [см. CustomUserDetailService выше, UserServiceImpl выше, User выше].Day (Таблиця days): id (IDENTITY) ➡️ number ➡️ title [см. Day выше].Зв'язок: Одно до багатьох (@OneToMany) з Location [см. Day выше].Location (Таблиця locations): id (IDENTITY) ➡️ name ➡️ day_id (FK) [см. Location выше].Зв'язок: Багато до одного з Day [см. Location выше], Одно до багатьох з Operation [см. Location橋 выше].Operation (Таблиця operations): id (IDENTITY) ➡️ description ➡️ tools_and_materials ➡️ location_id (FK) [см. Operation выше].Зв'язок: Одно до багатьох з OperationImage [см. Operation выше].OperationImage (Таблиця operation_images): id (IDENTITY) ➡️ image_path (Текстове посилання на диск) ➡️ operation_id (FK) [см. OperationImage выше].

3. Безпека & Система Автоматичного Входу (JWT)Сервер працює в режимі Stateless (без сесій та cookies) [см. SecurityConfig выше].Перший вхід: Android надсилає логін/пароль ➡️ Сервер перевіряє хеш у БД ➡️ Генерує JWT-токен на 30 днів (алгоритм HS256, підпис SECRET_KEY) [см. JwtService выше, AuthController выше].Авто-вхід: Android зберігає токен. При кожному запуску прикріплює його в заголовок Authorization: Bearer <token> [см. SecurityConfig выше, JwtAuthenticationFilter выше].Перевірка: JwtAuthenticationFilter перехоплює запит, перевіряє підпис в оперативній пам'яті без запитів до MySQL і авторизує користувача [см. JwtAuthenticationFilter выше, JwtService выше].

4. Карта REST API Маршрутів (Endpoints)Усі контролери працюють без префіксу /api [см. DayController выше]. Повний базовий URL: http://<domain>:<port>/WeekEnds/ [см. RetrofitClient выше].🔐 Авторизація (Доступ відкритий для всіх)POST /auth/register — Реєстрація (приймає JSON: email, password, firstname, lastname) [см. AuthController выше]. Пароль автоматично хешується на рівні UserServiceImpl за допомогою BCrypt [см. UserServiceImpl выше, AuthController выше].POST /auth/login — Вхід (приймає JSON: username/email, password). Повертає JWT-токен [см. AuthController выше].GET /auth/me — Перевірка токена (повертає email поточного користувача) [см. AuthController выше].📅 Дні (Потрібен JWT Токен)GET /days — Отримати список усіх днів (полегшений DayDTO для головного екрана) [см. DayController выше].POST /days — Додати новий день (номер вираховується автоматично) [см. DayController выше].DELETE /days/{id} — Видалити день за ID (каскадом видалить все вкладені дані) [см. DayController выше].📍 Локації (Потрібен JWT Токен)GET /locations/by-day/{dayId} — Отримати локації суто для вибраного дня [см. LocationController выше].POST /locations — Створити нову локацію та прив'язати її до dayId [см. LocationController выше].DELETE /locations/{id} — Видалити локацію [см. LocationController выше].🛠️ Операції та Малюнки (Потрібен JWT Токен)GET /operations/by-location/{locationId} — Список операцій для локації разом із масивом посилань на фото [см. OperationController выше].POST /operations — Створити операцію (опис + інструменти) [см. OperationController выше].POST /operations/{id}/upload-image — Завантажити фото (Multipart). Файл зберігається у папку /uploads/ на сервері, а в БД записується відносний шлях [см. OperationController выше].DELETE /operations/images/{imageId} — Видалити конкретну фотографію з галереї операції [см. OperationController выше].DELETE /operations/{id} — Видалити операцію [см. OperationController выше].

5. Медіа-сервер (Роздача картинок)Файли фотографій не зберігаються в MySQL як LOB [см. OperationImage выше]. Вони лежать на диску сервера [см. OperationController выше]. Clase WebConfig налаштовує Spring Boot на роздачу статики [см. WebConfig выше]:Будь-який запит на http://skysong.biz.ua напряму відкриває файл із папки /uploads/ [см. 6. Вектор покращень (Що можна змінити в майбутньому)Валідація (spring-boot-starter-validation): Додати анотації @Email, @NotBlank, @Size на поля DTO, щоб сервер автоматично відхиляв некоректні запити до того, як вони дійдуть до сервісів.Refresh Token: Наразі видається один токен на 30 днів [см. JwtService выше]. Професійне покращення: видавати короткий Access Token (на 15 хвилин) та довгий Refresh Token (у базу даних) для безпечного безшовного оновлення сесії.Глобальний обробник помилок (@ControllerAdvice): Створити один клас, який буде перехоплювати всі помилки (наприклад, якщо ID дня не знайдено) і повертати Android-додатку красивий JSON об'єкт помилки { "status": 400, "message": "Здається, такий день уже видалено" } замість сирих системних трейсів.
